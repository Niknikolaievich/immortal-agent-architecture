# Learning Mechanism (Механизм обучения агента)

Данный документ описывает разницу между памятью (storage of experience) и обучением (change in behavior based on experience). Это критически важное различие для архитектуры «бессмертного» агента.

> *Примечание: термин «самообучающийся» в контексте данного проекта означает не автономное изменение весов модели, а структурированный процесс извлечения знаний из опыта и обновления поведенческих политик.*

## Память vs Обучение

**Память** — это сохранение опыта:
- Агент запомнил разговор с пользователем
- Агент записал факт в векторную базу данных
- Агент сохранил результат выполнения задачи

**Обучение** — это изменение поведения на основе опыта:
- Агент изменил способ ответа на определённый тип вопросов
- Агент обновил preference после получения обратной связи
- Агент скорректировал behavioral policy после ошибки

Память необходима для обучения, но недостаточна. Агент может помнить всё и ничему не научиться.

## Цикл обучения (Learning Loop)

Обучение агента формализуется как пятиэтапный процесс:

### 1. Experience (Опыт)
Агент взаимодействует с пользователем или средой. Результат сохраняется в Episodic Memory.
**Пример:** Пользователь попросил объяснить концепцию. Агент дал развёрнутый ответ. Пользователь сказал: «Слишком сложно, объясни проще».

### 2. Evaluation (Оценка)
Агент (или внешняя система) оценивает результат взаимодействия.
**Критерии оценки:**
- Удовлетворённость пользователя (явная обратная связь)
- Успешность выполнения задачи (task completion)
- Соответствие behavioral policies
**Пример:** Оценка: «Ответ был слишком сложным для данного пользователя».

### 3. Extraction (Извлечение)
Из опыта извлекается обобщённое знание или правило.
**Пример:** «Пользователь Николай предпочитает простые объяснения без технического жаргона».

### 4. Validation (Валидация)
Извлечённое знание проверяется на согласованность с существующей памятью и policies.
**Проверки:**
- Не противоречит ли новое знание уже сохранённым фактам?
- Не нарушает ли оно behavioral policies?
- Достаточно ли доказательств для обновления?
**Пример:** Проверка: «В предыдущих диалогах пользователь также просил упрощать. Знание согласовано».

### 5. Memory / Policy Update (Обновление)
Если валидация прошла успешно — обновляется соответствующий компонент Agent Identity State:
- **Semantic Memory:** добавляется новый факт
- **Preferences:** обновляется предпочтение пользователя
- **Behavioral Policies:** корректируется правило поведения
**Пример:** Обновление preferences: «Пользователь Николай → стиль общения: простой, без жаргона».

## Типы обучения

### 1. Явное обучение (Explicit Learning)
Пользователь напрямую даёт обратную связь:
- «Это неправильно»
- «Запомни, что я предпочитаю X»
- «Не делай так больше»

Агент немедленно обновляет соответствующий компонент состояния.

### 2. Неявное обучение (Implicit Learning)
Агент выявляет паттерны из поведения пользователя:
- Пользователь всегда игнорирует развёрнутые ответы
- Пользователь чаще задаёт вопросы по определённой теме
- Пользователь корректирует формулировки агента

Агент предлагает обновление preferences, но требует подтверждения пользователя.

### 3. Откат обучения (Learning Rollback)
Если агент «научился» чему-то неправильному (см. [recovery.md](./recovery.md), раздел 9):
- Пользователь может инициировать откат: «Забудь, что ты запомнил X»
- Система загружает предыдущую версию компонента состояния
- Изменение логируется для аудита

## Связь с другими компонентами архитектуры

Механизм обучения напрямую взаимодействует с:
- **Memory Model** (см. [memory-model.md](./memory-model.md)) — обучение обновляет Semantic Memory и Preferences
- **Identity State** (см. [identity-state.md](./identity-state.md)) — обучение изменяет компонент Preferences и Behavioral Policies
- **Recovery Protocol** (см. [recovery.md](./recovery.md)) — откат ошибочного обучения

## Ограничения текущей версии (v1)

В текущей версии архитектуры:
- Обучение не изменяет веса модели (это требует fine-tuning, что выходит за рамки проекта)
- Обучение ограничено обновлением preferences, policies и semantic memory
- Валидация знаний выполняется по упрощённым правилам (в будущих версиях — через формальную верификацию)

> *Примечание: данный механизм обучения является базовой спецификацией (v1) и будет расширяться по мере развития архитектуры.*
