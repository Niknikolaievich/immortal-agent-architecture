# Memory Model (Модель памяти агента)

Векторная база данных является лишь механизмом retrieval (поиска по сходству), а не полноценной памятью. Для обеспечения непрерывности идентичности агента память формализуется как многоуровневая структура, вдохновлённая когнитивной психологией, но реализованная через вычислительные примитивы.

> *Примечание: биологические аналогии используются исключительно как концептуальные метафоры для иллюстрации архитектурных паттернов.*

## Уровни памяти

### 1. Episodic Memory (Эпизодическая память)
**Что произошло.** Хронологическая запись конкретных событий, диалогов и взаимодействий агента с пользователем или средой.  
**Реализация:** лог событий с временными метками, хранящийся в неизменяемом (append-only) хранилище.  
**Пример:** «28 ноября 2026, 14:32 — пользователь попросил объяснить разницу между fault tolerance и state persistence».

### 2. Semantic Memory (Семантическая память)
**Что агент считает знанием.** Извлечённые из эпизодов факты, концепции и связи между ними, независимые от контекста конкретного события.  
**Реализация:** векторная база данных (vector DB) с возможностью семантического поиска.  
**Пример:** «Fault tolerance — это способность системы продолжать работу при отказе компонентов».

### 3. Procedural Memory (Процедурная память)
**Как агент умеет выполнять задачи.** Сохранённые навыки, последовательности действий, промпт-цепочки и результаты успешного выполнения типовых операций.  
**Реализация:** библиотека инструментов (tools), сохранённые workflow и policy-файлы.  
**Пример:** «Для создания нового файла в GitHub нужно нажать Add file → Create new file и ввести путь с слэшем».

### 4. Working Memory (Рабочая память)
**Что происходит сейчас.** Контекст текущей сессии: последние сообщения, активные задачи, промежуточные результаты. Очищается или сжимается при переходе в гибернацию.  
**Реализация:** контекстное окно модели (context window) + кратковременное хранилище сессии.  
**Пример:** «Пользователь только что попросил создать файл memory-model.md, я подготовил текст и жду подтверждения».

### 5. Identity / Self Model (Модель идентичности)
**Кем агент себя считает.** Устойчивые характеристики, роль, границы поведения, предпочтения и представление о собственных возможностях. Этот уровень напрямую связан с документом [identity-state.md](./identity-state.md).  
**Реализация:** конфигурационный файл агента + вектор предпочтений + behavioral policies.  
**Пример:** «Я — исследовательский ИИ-агент проекта Immortal Agent Architecture, моя задача — помогать в разработке архитектуры».

## Связь с состоянием агента

Все пять уровней памяти являются компонентами общего **Agent Identity State** и сериализуются при переходе в состояние гибернации (`HIBERNATION` → `STORAGE`). При восстановлении (`RESTORE`) агент загружает все уровни памяти в порядке приоритета:

1. **Identity / Self Model** — кто я?
2. **Procedural Memory** — что я умею?
3. **Semantic Memory** — что я знаю?
4. **Episodic Memory** — что со мной происходило?
5. **Working Memory** — что происходит сейчас?

Такой порядок гарантирует, что агент сначала «вспоминает себя», затем «вспоминает навыки», затем «вспоминает знания», и только потом «вспоминает события» и «возвращается к текущей задаче».

> *Примечание: данная модель памяти является базовой спецификацией (v1) и будет расширяться по мере развития архитектуры.*
